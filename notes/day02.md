## 今日学んだこと

- **POSIXモードと Bash の関係**
  - `set +o posix` は Bash の POSIX 互換モードを **明示的に解除** するコマンド。
  - POSIX モードでは一部の Bash 機能（`[[ ]]`、配列展開、ヒアストリングなど）が使えない。
  - Homebrew は macOS / Linux の両対応であり、環境に依存しない安全な実行を保証するため、まず POSIX モードを明示的に「OFF」にしている。
  - macOS の `bash` は古い（v3.2.57）ため、挙動確認実験を行った。

- **`[[ -z "${PWD-}" ]]` の挙動確認**
  - `${VAR-}` は「変数が未定義なら空文字を返す」構文。
  - `${VAR:-}` との違いを実験で検証し、どちらも未定義・空文字を安全に判定できることを確認。
  - ただし Homebrew 内では記述揺れがあり、L7・L33 は `:-`、L16 は `-` を使用していた。
  - これは「未定義チェック」中心か「未定義＋空文字チェック」中心かの違いによるものと推定。

- **`$PWD` の妥当性チェック**
  - `[[ -z "${PWD-}" ]]` → 未定義チェック  
  - `[[ -d "${PWD}" ]]` → ディレクトリ存在チェック  
  - `[[ -r "${PWD}" ]]` → ディレクトリ読み取り権限チェック  
  - 実験の結果、`rm -rf` で削除されたディレクトリ内にいる場合は `getcwd` が失敗し、実際に Bash が `$PWD` を参照できなくなることを確認。
  - そのような異常状態で `brew` を実行すると、エラーで安全に終了するよう設計されている。

- **`$HOME` の未設定チェック**
  - `$HOME` はユーザーのホームディレクトリを指す環境変数。  
    macOSでは通常 `/Users/<username>`。
  - Homebrew は `$HOME` を利用して設定ファイル（`~/.config/brew/`）やキャッシュディレクトリを参照するため、未定義だと動作不能。
  - `if [[ -z "${HOME:-}" ]]` で明示的に検出し、メッセージを出して終了する。

- **macOS と Linuxbrew**
  - Homebrew のコードは macOS 専用ではなく、Linux でも動作可能。
  - `linuxbrew-core-migration.rb` などのコードから、内部的に macOS / Linux の差異を吸収する設計であることを確認。
  - そのため POSIX 互換性や環境変数チェックが慎重に書かれている。
